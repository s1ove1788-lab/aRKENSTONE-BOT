# Бот заказов для MAX (роли: менеджер, курьер, производство)

Менеджер присылает PDF → заказы попадают в Google Таблицу → курьеры и производство
видят свои списки в боте, все получают уведомления о новых заказах.

## Файлы для GitHub (все загружаются в репозиторий)

`bot.py`, `config.py`, `max_client.py`, `logic.py`, `sheets.py`, `pdf_parser.py`, `requirements.txt`
(при обновлении `pdf_parser.py` и `requirements.txt` менять не нужно)

### Как обновить уже работающего бота
1. Откройте репозиторий на GitHub → **Add file → Upload files**.
2. Перетащите ВСЕ файлы из списка выше (старые `bot.py`, `pdf_parser.py` заменятся, остальные добавятся).
3. **Commit changes**. Bothost пересоберёт бота сам (если нет, нажмите «Перезапустить» в панели).
4. Новых переменных окружения не нужно. Нужны прежние: `MAX_BOT_TOKEN`, `SHEET_ID`,
   `GOOGLE_CREDENTIALS_JSON`, `MANAGER_IDS`.

## Как это работает для людей

Каждый пишет боту `/start` и выбирает роль (сменить: `/role`, выйти: `/stop`, свой ID: `/id`).

**👔 Менеджер** (только те, чей ID указан в `MANAGER_IDS`)
- присылает PDF в чат бота: новые заказы добавляются в таблицу, дубли пропускаются;
- кнопка «Таблица заказов» открывает Google Таблицу, где её можно править;
- кнопка «Таблица остатков» открывает прямо в боте текстовый экран с текущими остатками по всем размерам
  и кнопкой «Внести остаток» (так же, как у производства).
  Чтобы правка работала, менеджеру нужно дать доступ к таблице на его Google-аккаунт
  (кнопка «Настройки доступа» в самой таблице). Сам лист «Остатки» тоже есть в этой таблице.

**🚚 Курьер**
- «Доставки» → «По России: N шт.» и «Город: N шт.»;
- Россия: заказы сгруппированы по каналу и номеру отгрузки (например «ЯМ СГТ №91300462 · 4 шт.»),
  отмечаются сразу все вместе;
- Город: список адресов, внутри адреса карточка вида
  `180/30 чёрная тел.: +7 958 724-18-38, 5976` (слово «доб.» заменяется запятой);
- кнопки «✅ Доставлен сегодня» и «❌ Не доставлен».

**🏭 Производство**
- «План производства»: все будущие доставки по датам, например `28.окт — 180/30 чёрная ×2`;
- «Остатки»: кнопки 120.04, 120.06 … 200.06 → нажали → отправили число → строка добавилась
  на лист «Остатки»; кнопка «Текущие остатки» показывает последние значения.
- «Отгрузка» (привязана к сегодняшней дате): экран показывает, что по таблице нужно отгрузить сегодня,
  что уже отгружено и что осталось. Производство пишет боту, что отдало в доставку:
  `160/30 ч` (одна чёрная), `180/30 б 2` (две белые); несколько позиций — каждая с новой строки.
  Бот записывает отгрузку на лист «Отгрузки» и вычитает количество из остатка.
  Если остатка по размеру в таблице нет или его меньше, чем отгрузили, бот ничего не вычитает
  и честно об этом пишет (отгрузка при этом всё равно записывается).
  Заказы с диапазоном дат (22-27 окт) попадают в «к отгрузке» каждый день диапазона.

## Что бот создаёт в Google Таблице сам
- в листе заказов появляется столбец **«Статус»**;
- листы **«Отгрузки»**, **«Пользователи»** (кто какую роль выбрал; роль можно поправить прямо в таблице,
  бот перечитывает список раз в 5 минут), **«Подписчики»** (групповые чаты), **«Остатки»**.
Эти листы не удаляйте.

## «Чистый чат»
- У каждого человека в диалоге одно сообщение-меню: бот правит его на месте, а не шлёт новые.
- Сообщения людей (числа остатков, «160/30 ч», команды) бот сразу после обработки пытается удалить.
  Удаление чужих сообщений зависит от разрешений MAX. Если MAX не разрешит, бот один раз напишет об этом
  в логах и будет присылать меню заново внизу чата (старое меню удаляется).
- PDF менеджера после успешной загрузки в таблицу тоже удаляется из чата.
- Уведомления о новых заказах остаются в чате (это сами сообщения, ради которых бот нужен),
  а меню после них поднимается вниз.
- Выключить всё это: переменная окружения `CLEAN_CHAT=0`.

## Важные правила работы
- **Какая дата считается «сегодня».** По России (картон) смотрим «Дата отгрузки», по городу «Дата доставки».
  Если в дате диапазон (22-27 окт), заказ показывается каждый день внутри диапазона.
  Если на сегодня нет ни одной доставки по России, раздел «По России» у курьера не показывается.
- **«Доставлен»** не удаляет строку: в столбец «Статус» записывается «Доставлен 27.10 14:30».
  Заказ пропадает из списков курьера и плана производства, а менеджер сохраняет историю.
  Любое слово, написанное вручную в «Статус», тоже убирает заказ из списков (например «Отмена»).
- **«Не доставлен»** оставляет заказ в таблице без отметки. По России (СГТ и др.) курьер видит
  только заказы на сегодняшнюю дату: на следующий день такой заказ из его списка уходит.
  По городу недоставленные адреса остаются у курьера с пометкой ⏰ («не доставлено в прошлые дни»).
- Уведомления о новых заказах получают все роли. Чтобы курьерам не приходили,
  уберите `"courier"` из `NOTIFY_ROLES` в `config.py`.
- Для группового чата: добавьте бота в чат и напишите там `/subscribe`
  (чат будет получать только уведомления).

## Первый запуск (если настраиваете с нуля)
1. Google Таблица + ключ + доступ сервисному аккаунту (шаги 1–7 в старой инструкции:
   Google Cloud → включить Google Sheets API → сервисный аккаунт → ключ JSON → дать его `client_email`
   доступ «Редактор» к таблице).
2. Репозиторий на GitHub с файлами выше.
3. Бот на Bothost: платформа Max, Python, токен, локация «Россия (Москва)», адрес репозитория,
   переменные: `MAX_BOT_TOKEN`, `SHEET_ID`, `GOOGLE_CREDENTIALS_JSON` (содержимое JSON-файла целиком).
4. Напишите боту `/start`, затем `/id`; ID менеджера впишите в `MANAGER_IDS` (только число; несколько через
   запятую) и перезапустите бота. После этого менеджер выбирает роль «Менеджер».

## Что можно подправить в коде
- Цвета артикулов и названия каналов: `COLOR_CODES`, `CHANNEL_ALIASES` в `pdf_parser.py`.
- Какие каналы считаются «городом»: `CITY_CHANNELS` в `logic.py`.
- Список размеров для остатков: `STOCK_CODES` в `config.py`.

## Яндекс Маркет (в разработке)
Команда `/ym` (только менеджер) показывает магазины на Маркете и по паре свежих заказов
с замаскированными персональными данными, чтобы увидеть, какие поля отдаёт API.
Нужна переменная окружения `YANDEX_MARKET_TOKEN` (токен только на чтение:
право «Просмотр информации о заказах»). Токен никому не пересылайте.
Если токен случайно попал в переписку или в код, удалите его в кабинете Маркета и создайте новый.
